# 任务记录

根据真实对话整理，不是开始前的问卷。保留用户决定与 AI 建议的区别；没有讨论、未验证、未练习分别标注，不能自动补齐。

保存位置属于本 skill 的实现约定，不是原实践文档的要求，用户可覆盖：优先更新用户指定的原记录；新记录遵守当前项目已有文档目录约定。没有约定时在当前工作区 `docs/ai-learning/YYYY-MM-DD/` 下创建语义明确的 Markdown 文件，并告知路径；日期使用实际任务日期，不固定为本 skill 创建日期。无可写工作区时在对话中给出 Markdown。不要覆盖同名但不同的任务；复盘补充日期和新增证据，保留有意义的历史状态。

下面主体沿用参考模板。为覆盖未交付和不适用情形，本 skill 补充状态约定：未交付时据实写“进行中”或“暂停”，不得被两个交付状态强迫标为已交付；符合 [理解与迁移](understanding.md) 中全部不适用条件的任务可写“已交付、理解检查不适用”，不能仅因操作简单而采用该状态。需要学习但被用户暂缓的内容仍记为待理解，不使用不适用状态。

```markdown
# 任务名称

## 已确认的目标

- 要解决的问题：
- 什么结果算完成：
- 关键约束（如有）：

## 我的关键判断

- 比较过的候选方案及其取舍：
- 需要由我决定的关键事项：
- 选择了什么：
- 为什么这样选：
- 未选择其他方案的原因：
- 接受了什么代价或限制：
- 尚未决定的事项：

## AI 完成的工作

- 执行内容：
- 交付结果：

## 验证与未知

- 已实际执行的检查及结果：
- 尚未验证的假设：
- 仍待确认的问题：

## 我的理解

- 脱稿解释的核心逻辑：
- 可能失效的场景：
- 后续修改入口：

## 迁移练习

- 改变了什么：
- 我的预测及理由：
- 实际结果：
- 理解偏差：

## 掌握程度

- [ ] 能脱稿解释
- [ ] 能预测变化
- [ ] 能独立修改
- [ ] 能定位错误

状态：已交付、待理解 / 已交付、已理解
已理解的范围：
仍需补充的部分：
```

在迁移练习条目中据实注明进行中、暂缓、已完成或不适用及依据，并记录提示帮助；练习完成不自动勾选掌握程度。必要时注明验证来源和待核对状态。暂停学习需续做时补充简短“续做位置”：当前模式、已完成工作、暂停点和下一步，避免复述所有聊天。再次复盘时补充上次练习的实际结果和缺口是否改善，未验证的改善不能写为事实。

整理后交用户核对，不替其确认判断、证据和掌握程度；核对前可保存为草稿。未执行的检查不能写成实际结果，计划练习不能写成已完成。
