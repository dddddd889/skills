# 名词概念讲解

宗旨：让读者一眼看清一个名词/概念在整个体系里的"定位"，而不是背一段抽象定义。

## 触发时机

生成技术文档、设计文档、说明文档等内容，遇到需要向读者解释清楚的名词或概念时，使用本技能。

## 讲解优先级

1. **优先用图**：从以下几种图里，挑最贴合该概念性质的一种或几种，把概念在体系里的定位画出来：
   - **时序图**：概念在一次交互/流程中，什么时候出现、和谁发生什么调用或数据往来。
   - **架构图**：概念在整体系统结构中，和上下游、左右邻居分别是什么关系。
   - **穷尽场景路径**：把这个概念可能出现的典型使用路径/分支都列出来（例如正常路径、异常路径、边界路径），让读者建立全貌认知，而不是只看到一种用法。
2. **图讲不清楚的部分，再用文字补充**：
   - 不要用词典式的抽象定义（"XX 是一种……的机制"）。
   - 优先举一个具体场景，用这个场景把名词的含义"套"出来，而不是先定义再举例。

## 输出建议顺序

对每一个需要讲清楚的名词/概念，建议按下面顺序组织内容：

1. 一句话点明这个概念在整体中的位置（它是谁的一部分，谁依赖它）。
2. 配图（时序图 / 架构图 / 场景路径，按需选择，不必全部都画）。
3. 文字说明 + 具体场景例子，补充图里没覆盖到的细节。

## 注意事项

- 不是每个名词都要画三种图，简单的概念（没有交互、没有结构关系）可以只用"一句话定位 + 例子"。
- 图和文字不是互斥关系，图负责让读者看懂全貌，文字负责讲清楚细节和边界。
- 使用 mermaid 语法画图（`sequenceDiagram` / `flowchart` / `graph`），方便在 Markdown 中直接渲染。
